Encryption: how a message stays private

Farhan is at a café in Hazratganj, on the café’s free Wi-Fi. He types “Meet me at 5 pm” to his cousin Sana. The message passes through the café’s router, his telecom company, the internet, WhatsApp’s servers and Sana’s telecom before it reaches her phone. Any of them could, in principle, look inside. Encryption decides who actually can. A PM needs this vocabulary: every privacy promise, every feature that needs to read messages, and every argument with a regulator comes back to it.

What can be seen on the way

Without any encryption, everyone along the path could read “Meet me at 5 pm”. With encryption in transit, the lines are protected but WhatsApp’s server unlocks and relocks the message, so the company could read it. With end-to-end encryption, only Farhan’s and Sana’s phones can read it; everyone in between, WhatsApp included, passes on a locked box ({{REF:path}}). The ideas below explain how that works, from the smallest building block up.

1. Hashing: a fingerprint of any data

Everyday picture. Grinding masala. Whole spices go in and a powder comes out. The same spices always give the same powder, but nobody can turn the powder back into whole spices. A fingerprint works the same way: it identifies you, but no one can rebuild you from it.

How it works. A hash function turns any data, a word or a whole film, into a short code of fixed length. SHA-256, the most common, always gives 64 characters. Three rules make it useful: the same input always gives the same code; changing even one letter changes the whole code; and there is no way back from the code to the input ({{REF:hash}}).

Where it’s used. Websites should never store your password, only its hash. At login they hash what you type and compare. WhatsApp puts the fingerprint of every photo and video inside the message, so the receiving phone can check that the file it downloaded wasn’t changed on the way. The maths of a leak. Hashes can’t be reversed, but they can be guessed. An 8-letter password in small letters has 26⁸ ≈ 2.1 × 10¹¹ possibilities. A gaming graphics card can try about 10¹⁰ fast hashes a second, so it finds the password in about 21 seconds. With a hash designed to be slow (bcrypt, for example) it manages about 10⁴ a second, and the same search takes about 8 months. Adding a random salt (extra characters, different for each user) before hashing means attackers must crack each person separately. Real example. In 2012 LinkedIn lost millions of password hashes that were fast and unsalted; most were cracked within days. PM decision: insist on slow, salted hashes; check new passwords against lists of leaked ones; prefer one-time passwords or passkeys where you can.

2. One shared key: symmetric encryption

Everyday picture. A steel almirah at home with two copies of its key. Whoever holds a copy can lock it and open it.

How it works. In symmetric encryption the same key locks and unlocks. The standard method, AES, scrambles data so thoroughly that without the key it looks like random noise. It is fast enough to lock video as it is recorded, which is why WhatsApp uses AES-256 for the content of every message and file. How strong is it? A 128-bit key has 2¹²⁸ ≈ 3.4 × 10³⁸ possible values. At a trillion guesses a second, trying them all would take about 10¹⁹ years, roughly 800 million times the age of the universe. The catch: Sana needs a copy of the key. If Farhan sends the key over WhatsApp, anyone watching gets the key too. This is the key-sharing problem, and the next three ideas exist to solve it ({{REF:locks}}).

3. Public and private keys: open padlocks anyone can close

Everyday picture. Sana gives out open padlocks to anyone who asks. Farhan puts his note in a box and snaps her padlock shut. Now even Farhan can’t open the box; only Sana, who kept the only key, can.

How it works. Each person has a key pair. The public key is the open padlock: shared freely, stored in a directory. The private key is the only key that opens it, and it never leaves the owner’s phone. Anything locked with Sana’s public key opens only with her private key. Key pairs are slow, so in practice they lock something small, a fresh AES key, and the AES key locks the message. The maths of scale. If 1,000 people each want a private line to every other person using shared keys, they need 1,000 × 999 ÷ 2 = 4,99,500 secret keys, each handed over safely. With key pairs, each person needs just one: 1,000 public keys in a directory ({{REF:keys}}).

Real example. The padlock in your browser’s address bar when you open your bank’s website: the bank’s server sends its public key, and your browser uses it to set up the connection. PM decision: someone must run the directory of public keys; for WhatsApp, it is WhatsApp’s own server. That raises the obvious question, what if the directory lies? The answer is the security code: a check that both phones hold the same padlocks.

4. Digital signatures: a seal only you can make

Everyday picture. A king’s wax seal, pressed with his ring. Anyone can recognise it; only the king can make it; and a broken seal shows the letter was opened.

How it works. To sign, the sender hashes the message and locks the hash with their private key. To check, anyone opens it with the sender’s public key and compares it with their own hash of the message. If they match, the message came from the key’s owner and wasn’t changed by even one character ({{REF:sign}}).

Real examples. Phones install an app update only if it is signed with the same key as the installed app, so a fake “WhatsApp Gold” file sent on a group can’t replace the real app. Aadhaar eSign and documents in DigiLocker carry the issuer’s digital signature. PM decision: guard the signing key as the company’s most valuable secret, and never train users to install app files from links; that is how many Indian “bank KYC” and “PM scheme” scams spread malware.

5. Agreeing a secret in public: key exchange

Everyday picture. Mixing paint ({{REF:paint}}). Riya and Farhan both start with the same yellow, which anyone can see. Riya secretly adds red and gets orange; Farhan secretly adds blue and gets green. They swap orange and green in public. Riya adds her red to Farhan’s green; Farhan adds his blue to Riya’s orange. Both end up with the same brown. Someone who saw yellow, orange and green can’t unmix them to find the brown.

How it works, with small numbers. This is Diffie–Hellman key exchange (1976). “mod” means the remainder after dividing, like clock arithmetic. Public numbers: 23 and 5. Riya picks a secret, 6, and sends 5⁶ mod 23 = 8. Farhan picks a secret, 15, and sends 5¹⁵ mod 23 = 19. Riya computes 19⁶ mod 23 = 2; Farhan computes 8¹⁵ mod 23 = 2. Both have the secret 2, and it never travelled. With numbers hundreds of digits long, working backwards from 8 and 19 is practically impossible. Real example. Every HTTPS connection and every new WhatsApp chat starts this way; WhatsApp uses a modern version called Curve25519. PM decision: because fresh secrets are cheap, systems can make new ones often, which limits the damage when one leaks.

6. In transit or end to end

Everyday picture. A courier company that opens your parcel at its warehouse, checks it and seals it again, against a locked box that only the receiver has a key for. In the second case the courier sees only the address label.

How it works. With encryption in transit (TLS, the “S” in HTTPS), the message is locked between your phone and the company’s server, unlocked there, and locked again for the receiver. The company can read and store it. With end-to-end encryption, the message is locked on your phone and only the receiver’s phone can open it; the server passes on a box it can’t open ({{REF:e2e}}).

Real examples. Gmail is encrypted in transit, which is how it can filter spam and suggest replies. Telegram’s normal chats are too: stored on its servers so they sync to any device, and readable by the company. WhatsApp, Signal and iMessage are end to end, and Messenger became end to end by default in December 2023. PM decision: end to end is a promise users can check and journalists will test. Every feature that needs the server to read messages must be dropped, moved onto the phone, or built another way.

7. How WhatsApp’s end-to-end encryption works

WhatsApp uses the Signal protocol, built by the makers of the Signal app and switched on for every WhatsApp chat in April 2016. It combines the ideas above in five steps.

(a) Keys are made on the phone. When you install WhatsApp, your phone creates an identity key pair (your long-term padlock and key), a signed pre-key, and a batch of one-time pre-keys. The public halves go to WhatsApp’s server. The private halves never leave your phone.

(b) Starting a chat with someone who is offline. Key exchange normally needs both people present, like the paint swap. But Sana’s phone might be switched off. So her phone has already left a stack of open padlocks, the one-time pre-keys, at the “post office”. Farhan’s phone collects one, does the key exchange with it on its own, and sends the first message along with what Sana needs to make the same secret when she comes online ({{REF:prekey}}). The Signal protocol calls this X3DH.

(c) A new key for every message. From that first secret, each message gets its own key, made by turning a ratchet: a one-way step, like a car jack that only turns one way. Old keys are deleted as soon as they are used. So if a thief copies today’s key, yesterday’s messages stay locked: this is forward secrecy. And each time the other person replies, a fresh key exchange is mixed in, so a stolen key stops working after a round of messages ({{REF:ratchet}}). The everyday picture is a pad of one-time codes: each page used once, torn off and burned.

(d) Checking nobody is in the middle. The weak point is the directory. If an attacker, or a dishonest server, gave Farhan a fake padlock that looked like Sana’s, the attacker could open messages, read them and relock them with Sana’s real padlock. Neither would notice. So WhatsApp shows each pair a security code: 60 digits, or a QR code, made from both people’s identity keys. If the code on Farhan’s phone matches the code on Sana’s, nobody is in the middle ({{REF:mitm}}). WhatsApp also warns “security code changed” when a contact gets a new phone, and since 2023 it has checked keys automatically against a public log (key transparency).

(e) Groups, linked devices and backups. Groups use sender keys. Each member makes a group key and sends it once, privately, to every other member. After that, each message is locked once and the server copies it to every member, as for any group message. In Farhan’s 47-member group, setting up keys takes 47 × 46 = 2,162 private key messages; after that, each message is locked once, not 46 times. When someone leaves, keys are changed so they can’t read new messages. Linked devices (a laptop or a tablet) each get their own identity key, and messages are locked separately for each device: Sana with a phone and a laptop receives two copies. Backups go to Google Drive or iCloud and, by default, are not end to end. Since 2021, users can lock their backup with a password or a 64-digit key. The key is kept in a tamper-proof hardware vault that allows only a few wrong guesses. Lose the password and the 64-digit key, and the backup is gone for good; nobody can recover it.

8. What end-to-end encryption doesn’t hide

End to end protects what you say, not the fact that you said it ({{REF:hides}}). WhatsApp’s servers must know who is sending to whom, and when, or they couldn’t deliver anything. They also see your phone number, IP address, phone model and who is in which group. That information about messages is called metadata, and it can reveal a lot: a call to an oncologist at 11 pm says something even if nobody hears it. Beyond metadata: anyone holding your unlocked phone can read everything; the person you send to can screenshot or forward it; a backup that isn’t encrypted end to end can be read by whoever can open that cloud account; and when you report a chat, your phone sends the last few messages to WhatsApp for review. Spyware on the phone itself reads messages before they are locked: in 2019 WhatsApp found that the Pegasus spyware had targeted about 1,400 users, including Indian journalists and activists, and sued its maker, NSO Group; a US jury ordered NSO to pay about $168 mn in 2025.

9. The PM trade-offs

Feature or dutyWhy end to end makes it hardWhat WhatsApp does instead
Searching old chatsThe server can’t read, so it can’t searchSearch runs on the phone
Spam and scamsNo scanning of message textBehaviour signals (a new number messaging hundreds of strangers), user reports, rate limits, forward counts
AI summariesThe server can’t see what to summariseOpt-in “Private Processing” (announced 2025): the messages are handled in sealed hardware that even Meta says it can’t look into
A lost phoneNo readable copy exists anywhereBackups, encrypted if the user chooses; a clear warning at setup
MisinformationCan’t see what is spreadingForward limits and labels; fact-check tip lines on WhatsApp itself
Police requestsNo message content to hand overAccount details and metadata, under legal process

The traceability debate in India. Rule 4(2) of India’s IT Rules 2021 says a large messaging service must be able to identify the first originator of a message when a court or the government orders it, for serious crimes. WhatsApp argues that the only way to do this is to attach a fingerprint of the sender to every message sent by every Indian, just in case one is ever asked about, which would break the promise of end-to-end encryption for everyone. It challenged the rule in the Delhi High Court in May 2021, and in April 2024 its lawyer told the court that WhatsApp would leave India rather than break encryption. The court last heard the case in August 2024 and had not ruled as of September 2026. The government’s side is real too: a forwarded rumour that leads to violence has a source, and investigators want to find it. PM decision: in any market, know which promise you would refuse to break, and design the product (forward limits, labels, reporting) so that the company can do as much as possible without breaking it.

In the interview · How encryption comes up
  • “Should WhatsApp add AI summaries?” Only on the phone or in sealed processing, opt-in, because the server can’t read chats. Say what you give up: slower, fewer phones supported.
  • “How would you reduce scams on an encrypted app?” Use what the server can see: new accounts, messages to many strangers, reports, forwards. Warn users when a stranger sends a link or asks for money.
  • “A government asks you to trace a message.” Explain the trade-off: tracing one message means fingerprinting all of them. Offer metadata under legal process, forward limits and labels instead.
  • “What is end-to-end encryption, simply?” The message is locked on the sender’s phone and only the receiver’s phone has the key; the company carries a box it can’t open.
