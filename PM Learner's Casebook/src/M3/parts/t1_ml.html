Machine learning and AI: what a PM needs to know

Open Myntra and almost everything you see was chosen by a model: the order of the home feed, the “similar products” row, the size hint, the search results, even which banner appears. None of these was written as rules by a person. Each was learned from millions of past clicks, purchases and returns. A PM doesn’t build these models, but decides where they are worth building, what data they need, what a wrong answer costs, and how to tell if they work.

AI, machine learning, deep learning and GenAI

These four words are nested, like Russian dolls ({{REF:nest}}). Artificial intelligence (AI) is any computer system doing something we would call intelligent, including hand-written rules (“if cart value > ₹499, delivery is free” is not AI; a chess program written as rules once was). Machine learning (ML) is AI that learns patterns from examples instead of being told the rules. Deep learning is ML using large neural networks, good at messy inputs like photos, speech and text. Generative AI (GenAI) is deep learning that creates new text, images or code, rather than choosing from existing options.

Three ways a machine learns

Supervised learning learns from examples where the right answer is known (labelled data). Show it 10 lakh past orders, each marked “returned” or “kept”, with details like size, brand, price and the customer’s history, and it learns to predict the chance that a new order will come back. Unsupervised learning has no right answers; it finds groups by itself. Give it every shopper’s behaviour and it may find five clusters, such as “sale-only phone buyers” or “weekly beauty browsers”, which marketing can then name and target. Reinforcement learning learns by trial and reward, like a child learning to cycle: it tries an action (which banner to show), sees the reward (a click or not), and slowly shifts towards what works ({{REF:learn3}}).

How a model is trained, and how it fools you

Training means showing the model labelled examples and letting it adjust itself to make fewer mistakes. The labelled data is split three ways: about 70% to train on, 15% for validation (to tune settings and choose between models) and 15% for a final test the model has never seen. The test score is the honest one.

Overfitting is the classic trap. A student who memorises last year’s question paper scores 100% on it and fails the real exam. A model can do the same: it learns quirks of the training data (a brand that happened to have many returns in one bad week) instead of the real pattern. Training error keeps falling, but error on new data starts rising ({{REF:overfit}}). Data leakage is the sneakier trap: a column that secretly contains the answer. A return model that uses “refund issued” as an input looks 99% accurate in testing and is useless in real life, because at the moment of ordering nobody knows yet whether a refund will be issued.

Recommender systems, from the inside

The “you may also like” row is the most valuable model in e-commerce. It has one hard job: from a catalogue of, say, 50 lakh products, pick the 20 this person is most likely to want, in under 0.2 seconds. Two ideas sit underneath. Collaborative filtering uses what similar people did: “people who bought this kurta also bought these juttis”. It needs no understanding of the product, only lots of behaviour. Content-based filtering uses the product’s own features: colour, fabric, style, price. It works for brand-new products that nobody has bought yet.

Embeddings. Modern systems turn every product and every user into a list of numbers, an embedding, so that similar things sit close together, like cities on a map. Similarity is then measured by cosine similarity: how closely two arrows point the same way (1 = same direction, 0 = unrelated). Worked example with two made-up dimensions, “ethnic” and “casual” ({{REF:cos}}): kurta A = (0.9, 0.3), kurta B = (0.8, 0.4), T-shirt C = (0.1, 0.95). A·B = 0.9×0.8 + 0.3×0.4 = 0.84; divide by the lengths (0.95 × 0.89 ≈ 0.85): cosine ≈ 0.99, almost the same direction. A·C = 0.09 + 0.29 = 0.38; ÷ (0.95 × 0.96 ≈ 0.91) ≈ 0.41. So B is recommended next to A, and C isn’t. Real embeddings have a few hundred dimensions, but the arithmetic is the same.

The pipeline ({{REF:recpipe}}). Scoring 50 lakh products with a heavy model for every page view would take too long and cost too much. So systems work in stages: retrieval quickly pulls about 500 candidates whose embeddings are close to the user’s; ranking runs a detailed model on those 500 to predict the chance of a click, purchase or (better) a kept purchase; re-ranking applies business rules: hide out-of-stock items, avoid showing ten near-identical kurtas, place sponsored products in fixed slots. PMs own that last stage most directly.

Neural networks, in one picture

Visual search runs on a neural network: layers of simple units, each adding up its inputs with different weights and passing the result on. The first layers of an image model learn to spot edges and colours, the middle layers patterns such as embroidery or a collar, and the last layers whole ideas like “anarkali kurta” ({{REF:nnet}}). Training means nudging millions of weights, a little at a time, so the network’s guesses on labelled photos get less wrong. Nobody writes the rule “an anarkali flares below the waist”; the network works it out from thousands of labelled photos.

Generative AI: what changes for the PM

A classic model picks from options: a score, a label, a ranked list. A generative model writes something new: Amazon’s shopping assistant composes an answer from reviews; a seller tool writes a product description from a photo. Three things change. Wrong answers look confident: a generated answer can state a fabric that isn’t in the listing (a hallucination), so answers must be grounded in the product’s own data. Every answer has a running cost, paid per word generated, unlike a recommendation that is cheap once trained. And quality is harder to measure: there is no single right answer to compare against, so teams build test sets of questions with human ratings.

When it breaks

Models learn yesterday. After a big change (a new sale format, a pandemic, a price war) the patterns they learned stop holding, and accuracy falls silently; this is called drift. The only defence is monitoring live accuracy against fresh labels, and retraining on a schedule.

In the interview

“I’d start with a simple rule or a popularity baseline, then use a model only if it beats that baseline in an A/B test by enough to cover its cost. I’d train it on the outcome we actually want, bought and kept, not on clicks.”
